    The 4 API call docs

    Today's menu: four requests

    Every backend request in the flow, with what each answer does.

    Served by OrderRepository
    POST/v1/ordersCreate Order

    201 saves the order. A free order (total 0) skips payment. AwaitingPayment moves on to payment. Any other state throws.

    PATCH/v1/orders/{orderId}/paymentPay Order

    Always 200, so the body decides. Declined in the body means declined, even with ok: true. A bankCheck block means the bank wants a challenge.

    GET/v1/orders/{orderId}Order Status

    The polling call. Used while a manager approves a tab and while the barista brews.

    PATCH/v1/orders/{orderId}/stateUpdate State

    Cancelled when a tab approval times out. 409 means the barista already started.

    Tab approval timeout 5m TAB_APPROVAL_TIMEOUT

    Declined arrives as a 200

    The payment endpoint returns 200 whenever the order is valid. The state in the body wins over ok.

    New house rules for sequence diagrams

    The PR also changes the docs style guide, so future diagrams are drawn the same way.

    Real names

    Every participant is a real class, with no alias.

    Real calls

    Every message is a method that exists on its target. Leave out logging and getters.

    Returns only when used

    Draw a -->> only when something later uses the value.

    Branches that matter

    Use alt/opt only when the outcome changes, and label them in plain words.

    One flow per diagram

    About 15 messages max. Internals get their own diagram.

    Don't guess

    Anything that can't be checked goes in Gotchas, marked unverified.
